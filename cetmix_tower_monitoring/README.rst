This module adds current metrics of servers and jets to `Cetmix
Tower <https://tower.cetmix.com>`__.

- **Metrics** define what is measured: free disk, used memory, load or
  any custom value. A metric is shown as a progress bar, a gauge or a
  plain number.
- **Latest value** only: each server or jet keeps one value per metric,
  with the time of the last update. There is no history.
- **Thresholds** set the value state to Warning or Critical and can run
  a command or a flight plan when the state is reached. A value that is
  not updated in time becomes Stale.
- **Collectors** are ordinary Cetmix Tower commands, flight plans and
  webhooks. Python code saves a value with ``record_metric()``.

Metrics are shown to Cetmix Tower Managers and Root users on the server
and jet forms, kanban cards and lists. Metric definitions can be
exported and imported using YAML format.

Use Cases / Context
===================

Operators of `Cetmix Tower <https://tower.cetmix.com>`__ need to see at
a glance whether a server or a jet is healthy: how full its disk is, how
much memory is used, what the load is. Opening Grafana or another
monitoring tool for this means leaving Odoo and matching hosts by name.

This module shows the current value of such parameters directly on the
server and the jet in Odoo. It is not a replacement for Grafana or
Prometheus: it keeps only the latest value of each metric, with no
history and no graphs. Values are collected with the tools Cetmix Tower
already has: commands, flight plans, scheduled tasks and webhooks.

Configuration
=============

Installation
------------

Install the "Cetmix Tower Monitoring" module. It requires "Cetmix Tower
Webhook".

Access
------

Metrics, thresholds and metric values are available to the "Cetmix Tower
/ Manager" and "Cetmix Tower / Root" groups only. Users of the "Cetmix
Tower / User" group do not see them.

- Every Manager sees all metric definitions and their thresholds.
- A Manager sees the metric values of a server or a jet with the same
  rights as the server or the jet itself: a Manager added to "Users" of
  a server can read its values, a Manager added to "Managers" can also
  update them. Values of a jet also require access to the server of the
  jet.
- A Manager sees the metrics of a Jet Template with the same rights as
  the Jet Template itself, and changes them when added to "Managers" of
  the Jet Template.
- Root sees and changes everything.

Values are saved as the user that runs the code that calls
``record_metric()``: the user who runs the command, or the "Run as User"
of a webhook. This user must be able to write the server or the jet (be
in its "Managers"), otherwise the value is not saved.

Create a Metric
---------------

Go to "Cetmix Tower > Settings > Automation > Metrics" and click "New".

- **Name**. Metric name, shown on servers and jets.
- **Reference**. Unique reference used in ``record_metric()``. Leave
  blank to generate it from the name.
- **Widget**. How the value is shown:

  - Progress Bar: used amount of a total, e.g. disk or memory.
    ``record_metric()`` takes ``used`` and ``total``.
  - Gauge: a value with an optional maximum, e.g. CPU usage.
    ``record_metric()`` takes ``value`` and an optional ``total``.
    Without a maximum the value is shown as a number.
  - Number: a plain value, e.g. load average. ``record_metric()`` takes
    ``value``.

- **Note**. Detailed description of the metric: what is measured, how it
  is collected, what the values mean.
- **Unit**. Shown next to the value, e.g. ``GiB``, ``MiB`` or ``%``.
- **Stale After (minutes)**. A value not updated for this many minutes
  becomes Stale. The check runs every 5 minutes.
- **Show on Kanban**. Show this metric on the server and jet kanban
  cards.
- **Auto sync, minutes**. Run the collector of every value of this
  metric every N minutes. 0 turns auto sync off; otherwise use at least
  5. See "Collect values periodically".
- **Collector Command** or **Collector Flight Plan**. Used by the
  "Refresh" button. Set one of them, or none for metrics pushed by a
  webhook.

Choose a unit for progress bars
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

On the server and jet form, a progress bar shows whole numbers only:
45.2 of 100 is shown as ``45 / 100``, 3.1 of 8 as ``3 / 8``. Record
values in a unit where whole numbers are meaningful, e.g. GiB for disk
and MiB for memory, not GiB for memory.

Thresholds
----------

Add thresholds on the "Thresholds" tab of the metric.

- **Condition**. ``>=``, ``<=``, ``>``, ``<``, ``==``, or Stale.
- **Value**. Value to compare with. For progress bar metrics the
  condition compares used / total in percent: ``>= 90`` means "90 % or
  more is used". For gauge and number metrics it compares the value.
- **Severity**. Warning or Critical. While the condition matches, the
  value state is at least this severity. Stale thresholds have no
  severity: the value state is Stale anyway.
- **Action**. None, Run Command or Run Flight Plan. The command or the
  flight plan runs when the condition becomes matched: on the first
  sample that matches, or when the value crosses the limit again after
  it was back to normal. It does not run again on every sample while the
  condition stays matched.

Actions run on the server of the value. For a jet value they run on the
jet server for this jet.

Override thresholds for one server or jet
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Open a metric value from the "Monitoring" tab of a server or a jet and
add thresholds on the "Override Thresholds" tab. If a value has any
override thresholds, the metric thresholds are not used for it.

Collectors
----------

A collector is a Python command, or a flight plan with Python commands,
that measures the values and saves them with ``record_metric()``. SSH
commands cannot save values: run them from a Python command and parse
their output.

One collector can serve several metrics. It must name each metric
explicitly, because it is run the same way by the "Refresh" button and
by scheduled tasks, without any metric:

.. code:: python

   runner = server.with_context(no_command_log=True)
   disk = runner.run_command(tower_commands.get_by_reference("my_disk_bytes"))
   if disk["status"] == 0:
       used, total = disk["response"].strip().splitlines()[-1].split()
       server.record_metric(
           "disk_root", used=int(used) / 1024 ** 3, total=int(total) / 1024 ** 3
       )
   result = {"exit_code": 0, "message": "ok"}

Set the collector on the metric. To use another collector on one server
or jet, open its metric value from the "Monitoring" tab and set
"Collector Command" or "Collector Flight Plan" there.

Collect values periodically
~~~~~~~~~~~~~~~~~~~~~~~~~~~

There are two ways to run collectors periodically:

- **Auto sync**: set "Auto sync, minutes" on the metric. Every value of
  the metric that has a collector is collected every N minutes. Each
  collector runs once per server or jet, even if it serves several
  metrics. The check runs every 5 minutes, so a value is collected on
  the first check after N minutes have passed: the real interval can be
  up to 5 minutes longer than N. The command and flight plan logs of
  auto sync runs are deleted when the runs are done. Logs of commands
  and flight plans run by thresholds during these runs are kept. A run
  that could not start (e.g. another instance of the command is running)
  keeps its log.
- **Scheduled task**: create a scheduled task in "Cetmix Tower >
  Settings > Automation > Scheduled Tasks" that runs the collector
  command or flight plan on the servers or jets. Use it for a custom
  schedule. Its logs are kept, as are the logs of the "Refresh" button.

Metrics on Jet Templates
------------------------

Define metrics once on a Jet Template: jets of the template get them
automatically.

Open the Jet Template, go to the "Metrics" tab and add lines:

- **Metric**. The metric jets of this template get.
- **Environments**. Leave empty to apply to all jets of the template.
  Otherwise only jets whose environment is in the list get the metric.

Changes are applied to existing jets: a jet gets a value for each metric
that applies to it, and loses the values of metrics that do not apply
any more, together with their override thresholds. An environment used
in a Jet Template metric cannot be deleted.

Values added by a user, or by ``record_metric()`` from a command or a
webhook, are **manual**: the Jet Template never changes or deletes them.
If a jet already has a manual value for a metric that the Jet Template
adds later, the manual value is kept and no other value is added.

Jet Template metrics are exported and imported with the Jet Template in
YAML.

Metrics on Server Templates
---------------------------

Open a Server Template, go to the "Metrics" tab and add the metrics that
servers created from this template get.

Metrics are copied once, when a server is created from the template: the
server gets a value for each metric, in the Unknown state until the
first value is received. Later changes to the template metrics do not
change existing servers. Servers created without the template, or by
duplicating a server, do not get them.

Set collector overrides and override thresholds on the server values,
not on the template.

Server Template metrics are exported and imported with the Server
Template in YAML.

Push values with a webhook
~~~~~~~~~~~~~~~~~~~~~~~~~~

**⚠️ WARNING: You must be a member of the "Cetmix Tower / Root" group to
configure webhooks and authenticators.**

Create a webhook authenticator and a webhook in "Cetmix Tower > Settings
> Automation". Webhook code has no current server: resolve it from the
payload.

.. code:: python

   server = tower_servers.get_by_reference(payload["server_reference"])
   for item in payload["metrics"]:
       server.record_metric(
           item["reference"],
           value=item.get("value"),
           used=item.get("used"),
           total=item.get("total"),
       )
   result = {"exit_code": 0, "message": "ok"}

Use ``tower_jets.get_by_reference()`` for jets. Set the "Run as User" of
the webhook to a user that can write the servers or the jets.

Usage
=====

Where to see metrics
--------------------

- **Server and jet form**, "Monitoring" tab: every metric with its
  value, unit, state and last update. Progress bar metrics show a bar,
  gauge metrics with a maximum show a gauge, other metrics show the
  number. Gauge rows are taller than the others because each gauge is a
  chart.
- **Server and jet kanban**: the overall monitoring state and the
  metrics marked "Show on Kanban". Progress bar metrics show a bar with
  the used and total values, other metrics show the number.
- **Server and jet list**: rows are yellow when the overall state is
  Warning and red when it is Critical or Stale. The optional "Monitoring
  State" column shows the state.

On the form, progress bar labels are rounded to whole numbers: 45.2 of
100 GiB is shown as ``45 / 100``. The kanban card shows up to two
decimals: ``45.2 / 100 GiB``.

Open server and jet kanban and list views update by themselves when a
metric value or state changes, including updates from a scheduled task,
a webhook or auto sync. Several updates saved together refresh the view
once. An open form does not update by itself, so unsaved changes are
never lost: reload the page to see the new values.

Metric states
-------------

- **Unknown**: no value received yet.
- **OK**: the value is up to date and no threshold matches.
- **Warning** / **Critical**: the worst severity of the matching
  thresholds.
- **Stale**: the value was not updated within "Stale After (minutes)" of
  the metric.

The overall state of a server or a jet is the worst state of its
metrics, in this order: Critical, Stale, Warning, Unknown, OK.

Metrics from the Server Template
--------------------------------

A server created from a Server Template starts with the metrics of the
template, in the Unknown state until the first value is received.
Changes to the template later do not change the server: add or remove
its metrics on the "Monitoring" tab.

Metrics from the Jet Template
-----------------------------

A jet shows the metrics of its Jet Template on the "Monitoring" tab
together with its own ones. The "Manual" column tells them apart:

- **Manual** checked: added by a user, or by ``record_metric()`` for a
  metric the jet had no value for. The Jet Template never changes it.
- **Manual** not checked: added from the Jet Template. It is removed
  when the Jet Template metric is removed or no longer applies to the
  jet environment.

Auto sync
---------

Values of metrics with "Auto sync, minutes" update by themselves. Their
collector runs leave no command or flight plan logs: check "Last Update"
on the "Monitoring" tab to see when a value was received.

Refresh metrics
---------------

Click "Refresh" on the "Monitoring" tab of a server or a jet. It runs
each collector command or flight plan of its metrics once, even if a
collector serves several metrics. The button is shown only when at least
one metric has a collector.

Save a value from Python code
-----------------------------

In a Python command or in webhook code:

.. code:: python

   server.record_metric("disk_root", used=45.2, total=100.0)  # progress bar
   server.record_metric("cpu", value=37.5, total=100)  # gauge
   jet.record_metric("load_1", value=1.37)  # number

The metric must exist. A progress bar needs ``used`` and ``total``
greater than 0, a gauge or a number needs ``value``.

Example payload of the demo webhook "Monitoring: Push Metrics", sent as
a JSON POST request to
``<your Odoo URL>/cetmix_tower_webhooks/demo_metric_push``:

.. code:: json

   {
     "server_reference": "demo_server_1",
     "metrics": [
       {"reference": "disk_root", "used": 45.2, "total": 100.0},
       {"reference": "ram", "used": 3174, "total": 8192}
     ]
   }

Use the metric in threshold actions
-----------------------------------

A Python command run by a threshold, and every Python command of a
flight plan run by a threshold (including nested flight plans), has
these objects:

- ``metric``: the metric whose threshold runs the command.
- ``metric_value``: its current value, with ``value``, ``max_value``,
  ``state`` and ``last_update``.
- ``server`` and ``jet``: the server, and the jet when the value belongs
  to a jet.

.. code:: python

   used = metric_value.value
   total = metric_value.max_value
   if metric.reference == "disk_root" and metric_value.state == "critical":
       result = {"exit_code": 0, "message": "disk critical"}

In other commands ``metric`` and ``metric_value`` are ``None``. Webhook
and authenticator code does not have them; use ``tower_metrics`` and
``tower_metric_values`` to access metrics and values.

SSH commands and flight plan line conditions cannot use Python objects.
They get custom values instead:

+-------------------------------+-------------------------------------+
| Custom value                  | Content                             |
+===============================+=====================================+
| ``__metric__``                | metric reference                    |
+-------------------------------+-------------------------------------+
| ``__metric_value__``          | current value                       |
+-------------------------------+-------------------------------------+
| ``__metric_max__``            | total or maximum, empty if none     |
+-------------------------------+-------------------------------------+
| ``__metric_unit__``           | unit                                |
+-------------------------------+-------------------------------------+
| ``__metric_state__``          | new state                           |
+-------------------------------+-------------------------------------+
| ``__metric_previous_state__`` | state before this update            |
+-------------------------------+-------------------------------------+
| ``__metric_severity__``       | threshold severity, empty for Stale |
|                               | thresholds                          |
+-------------------------------+-------------------------------------+
| ``__server__``                | server reference                    |
+-------------------------------+-------------------------------------+
| ``__jet__``                   | jet reference, empty for a server   |
+-------------------------------+-------------------------------------+

In a Python command they are available in ``custom_values``:

.. code:: python

   used = float(custom_values.get("__metric_value__") or 0)
   state = custom_values.get("__metric_state__")
