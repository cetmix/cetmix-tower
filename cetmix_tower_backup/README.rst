Keep durable Jet backup records, capture the Jet's own variable values,
restore into a new Jet, and remove stored backup data through
configurable flight plans. Tower stores metadata; the plans create,
transfer, restore and delete the bytes.

Backups can be started from a Jet, a scheduled task, a Create Backup
command, or a waypoint backed by a Backup Template. Optional Git
integration captures sources and remotes and creates an independent Git
Project when restoring.

Use Cases / Context
===================

Waypoints belong to one Jet and restore its state in place. Backups keep
their metadata and captured configuration after that Jet is deleted, and
can restore into a new Jet. Use a waypoint for returning to an existing
Jet; use a backup when the recovery copy must outlive it.

Configuration
=============

**Create a Backup Template**

1.  Sign in as a Tower **Root** user.
2.  Open **Cetmix Tower**.
3.  Click **Commands**.
4.  Click **Flight Plans**.
5.  Create a Backup flight plan that writes backup data to your chosen
    destination.
6.  Set its **Access Level** to **Root**.
7.  Set every command and every Plan-action sub-plan it uses to **Root**
    too.
8.  Create a Root Restore plan that reads the stored data into a new
    Jet.
9.  Optionally create a Root Delete plan that removes the stored data.
10. Click **Jets**.
11. Click **Templates**.
12. Open the source Jet Template.
13. Open **Backups**.
14. Add a Backup Template.
15. Enter **Name**.
16. Select **Backup Flight Plan**.
17. Select **Restore Flight Plan**.
18. Select **Delete Flight Plan** when stored data needs explicit
    removal.
19. Enter **Keep Last**: ``0`` keeps all successful backups; a positive
    number limits them per source Jet.
20. Save the Backup Template.
21. Save the Jet Template.

**Configure a scheduled trigger**

1.  Open **Cetmix Tower**.
2.  Click **Automation**.
3.  Click **Scheduled Tasks**.
4.  Create a task.
5.  Set **Action** to **Backup**.
6.  Select **Backup Template**.
7.  Select target **Jets** from its Jet Template; leave **Servers**
    empty.
8.  Set the interval.
9.  Optionally add custom variable values.
10. Save.

**Configure a command trigger**

1. Open **Cetmix Tower**.
2. Click **Commands**.
3. Click **Commands** in that menu.
4. Create a command.
5. Set **Action** to **Create Backup**.
6. Select **Backup Template**.
7. Save.
8. Add the command to a flight plan running on a Jet, or select it in a
   scheduled **Command** task targeting a Jet.

**Configure a waypoint trigger**

1.  Open the source Jet Template.
2.  Open **Waypoints**.
3.  Open a waypoint template.
4.  Select **Backup Template** from the same Jet Template.
5.  Leave **Create Flight Plan** empty.
6.  Leave **Delete Flight Plan** empty.
7.  Optionally select a Root **Arrive Flight Plan**.
8.  Optionally select a Root **Leave Flight Plan**.
9.  Set every command and Plan-action sub-plan in those plans to
    **Root**.
10. Save.

**Author the plans**

1. Store object names, paths and recovery metadata with
   ``backup.update_metadata({...})`` in a Python command.
2. Pass non-secret destination parameters as trigger custom values.
3. Keep credentials in Tower keys, not custom values or metadata.
4. Keep the plans and commands at Root level; protected logs block
   lowering their access level, even after a plan leaves its Backup
   Template.
5. Configure **Available Variables, backup** and **Available Variables,
   restore** on the Backup Template to allow custom-value overrides in
   the Back Up and Restore dialogs. In-process Python
   ``restore(..., variable_values=...)`` remains available; RPC calls to
   ``restore()`` are rejected.
6. Set the measured size in MB from a Tower Python command with
   ``backup.write({"backup_size": 2048.25})``. Use 1 MB = 1,048,576
   bytes and pass fractional MB directly. Tower does not measure or
   assign the size itself.

+-----------------------------+---------------------------------------+
| Plan value or object        | Contract                              |
+=============================+=======================================+
| Trigger custom values       | Stored and replayed to Backup,        |
|                             | Restore and Delete                    |
+-----------------------------+---------------------------------------+
| Restore ``variable_values`` | Override the stored custom values     |
+-----------------------------+---------------------------------------+
| ``__backup_<key>``          | Metadata value; overrides a custom    |
|                             | value with the same name              |
+-----------------------------+---------------------------------------+
| ``__backup``                | Backup reference, applied after       |
|                             | metadata                              |
+-----------------------------+---------------------------------------+
| ``__backup_template``       | Backup Template reference, applied    |
|                             | after metadata                        |
+-----------------------------+---------------------------------------+
| ``__requested_jet_state__`` | Requested Jet state during Restore;   |
|                             | the Restore plan handles the          |
|                             | transition                            |
+-----------------------------+---------------------------------------+
| Python ``backup``           | Current backup on operation lines;    |
|                             | empty outside a backup run            |
+-----------------------------+---------------------------------------+
| Python ``tower_backups``    | Backup model shortcut                 |
+-----------------------------+---------------------------------------+
| Sub-plans                   | Receive custom values; do not         |
|                             | automatically receive the ``backup``  |
|                             | object                                |
+-----------------------------+---------------------------------------+
| Waypoint Arrive/Leave       | Receive backup values while the       |
|                             | waypoint template retains its Backup  |
|                             | Template; waypoint values win on      |
|                             | collisions                            |
+-----------------------------+---------------------------------------+

**Access boundary**

+----------------------------------+----------------------------------+
| Actor                            | Access                           |
+==================================+==================================+
| Root                             | Can read and configure backups   |
|                                  | and templates, and use the       |
|                                  | backup dialogs                   |
+----------------------------------+----------------------------------+
| Manager                          | Can trigger configured backups   |
|                                  | through waypoints, plans and     |
|                                  | schedules without seeing backup  |
|                                  | fields                           |
+----------------------------------+----------------------------------+
| User able to execute Tower       | Can call ``sudo()``; Root-only   |
| Python                           | ACLs, field groups and UI do not |
|                                  | isolate backups from that code   |
+----------------------------------+----------------------------------+

**Manage Backup Templates from Settings**

1. Sign in as a Tower **Root** user.
2. Open **Cetmix Tower**.
3. Click **Settings**.
4. Click **Backups**.
5. Click **Backup Templates**.
6. Create or open a template.
7. Select **Jet Template** and configure its flight plans and retention.
8. Click **Save**. Templates remain available on the Jet Template's
   **Backups** tab.

**Set a backup URL from a command**

1. Open the Backup flight plan's Tower Python command.
2. Write the backup address with
   ``backup.write({"url": "https://storage.example/backup.zip"})``.
3. Save the command. **URL** is read-only on the backup list and form;
   commands supply its value.

**Choose wizard variables**

1. Open **Cetmix Tower** → **Settings** → **Backups** → **Backup
   Templates**.
2. Open the template.
3. Select **Available Variables, backup** for the Back Up dialog and
   **Available Variables, restore** for the Restore dialog. An empty
   list permits no custom input in its corresponding dialog.
4. Click **Save**.

Usage
=====

**Take a backup**

1.  Open **Cetmix Tower**.
2.  Click **Jets**.
3.  Click **Jets** in that menu.
4.  Open the source Jet.
5.  Click **Back Up**.
6.  Select **Backup Template**.
7.  Optionally click **Add a line** under **Custom Values**.
8.  Select **Variable** from the template's available variables.
9.  Enter **Value**, or select **Option** for an option variable.
10. Click **Back Up** in the dialog.
11. Wait for **Running** to become **Done** or **Failed**.
12. Open **Metadata** to inspect the stored recovery details.
13. Open **Plan Logs** to inspect the plan result.

**Restore into a new Jet**

1.  Open **Cetmix Tower**.
2.  Click **Tools**.
3.  Click **Backups**.
4.  Open a **Done** backup.
5.  Click **Restore**.
6.  Select **Server**.
7.  Optionally enter **Name**; leave it blank to generate one.
8.  Optionally select **State**.
9.  Select **Environment** if the destination template requires it.
10. Optionally click **Add a line** under **Custom Values**.
11. Select **Variable** from the template's available variables.
12. Enter **Value**, or select **Option** for an option variable.
13. Click **Restore**.
14. Inspect the new Jet's flight plan log. If Restore fails immediately,
    the dialog opens the failed log and keeps the new Jet.

+---------------------+-----------------------------------------------+
| Recovery behavior   | Result                                        |
+=====================+===============================================+
| Destination         | A new Jet; the original Jet is not restored   |
|                     | in place                                      |
+---------------------+-----------------------------------------------+
| Repeated restore    | The backup remains Done and can be restored   |
|                     | again                                         |
+---------------------+-----------------------------------------------+
| Variable values     | Only the source Jet's own values were         |
|                     | captured; template, server and global values  |
|                     | and Jet secrets were not frozen               |
+---------------------+-----------------------------------------------+
| Default environment | Captured environment, then the Jet Template's |
|                     | default                                       |
+---------------------+-----------------------------------------------+
| Git bridge          | Restores captured Git configuration into      |
|                     | fresh records; source references and          |
|                     | aggregator source directories can differ      |
+---------------------+-----------------------------------------------+

**Delete a backup**

1.  Open **Cetmix Tower**.
2.  Click **Tools**.
3.  Click **Backups**.
4.  Open the backup.
5.  Click **Delete**.
6.  Wait for the Delete plan to finish; success removes the record.
7.  If **Deletion Failed** appears, inspect **Plan Logs**.
8.  Resolve the reported cause.
9.  Click **Delete** again to retry.
10. For a backup owned by a waypoint, delete the waypoint instead.

+----------------------------------+----------------------------------+
| Deletion condition               | Result                           |
+==================================+==================================+
| Running backup, deletion or      | Deletion is blocked              |
| Restore                          |                                  |
+----------------------------------+----------------------------------+
| Busy Jet or Delete plan          | Delete shows an error and leaves |
|                                  | the backup unchanged; retry      |
|                                  | later                            |
+----------------------------------+----------------------------------+
| Neither source Jet nor captured  | Form warns that only the record  |
| server remains                   | can be removed; stored data      |
|                                  | stays                            |
+----------------------------------+----------------------------------+
| No Delete plan                   | Record is removed immediately    |
+----------------------------------+----------------------------------+
| Source Jet deleted               | Completed backups survive; their |
|                                  | waypoint links are removed       |
+----------------------------------+----------------------------------+

**Check automatic clean-up**

1. Open **Cetmix Tower**.
2. Click **Tools**.
3. Click **Backups**.
4. Inspect the remaining records after the daily clean-up.

+----------------------------------+----------------------------------+
| Records                          | Daily clean-up behavior          |
+==================================+==================================+
| Unlinked Failed backups          | Removed regardless of Keep Last  |
+----------------------------------+----------------------------------+
| Excess Done backups per Jet      | Removed through the Delete plan  |
|                                  | when configured; otherwise only  |
|                                  | the record is removed and stored |
|                                  | backup data remains              |
+----------------------------------+----------------------------------+
| Backup being restored            | Counts toward retention and      |
|                                  | stays until a later clean-up     |
+----------------------------------+----------------------------------+
| Waypoint-linked backups          | Kept for the waypoint's          |
|                                  | lifecycle                        |
+----------------------------------+----------------------------------+
| Deletion Failed backups          | Kept for manual investigation    |
|                                  | and retry                        |
+----------------------------------+----------------------------------+
| Orphaned Done backups            | Kept                             |
+----------------------------------+----------------------------------+
| Busy or locked Jet / Delete plan | Deferred until a later clean-up; |
|                                  | other backups can still be       |
|                                  | processed                        |
+----------------------------------+----------------------------------+

**Inspect backup size**

1. Open **Cetmix Tower**.
2. Click **Tools**.
3. Click **Backups**.
4. Read **Backup Size (MB)** in the list.
5. Open a backup to read **Backup Size (MB)** on its form.

+------------------+--------------------------------------------------+
| Size value       | Meaning                                          |
+==================+==================================================+
| Backup Size (MB) | Stored Float supplied by a Tower command using 1 |
|                  | MB = 1,048,576 bytes; fractional values are      |
|                  | retained and the value starts at 0 until         |
|                  | supplied                                         |
+------------------+--------------------------------------------------+

**Open the backup URL**

1. Open **Cetmix Tower**.
2. Click **Tools**.
3. Click **Backups**.
4. Open a backup.
5. Click **URL** when the backup command has supplied one.

========================= ======
List state pill           Color
========================= ======
Done                      Green
Running                   Blue
Deleting                  Orange
Failed or Deletion Failed Red
========================= ======

+----------------------------------+----------------------------------+
| Wizard custom values             | Behavior                         |
+==================================+==================================+
| Corresponding Available          | No custom values accepted in     |
| Variables list empty             | that dialog                      |
+----------------------------------+----------------------------------+
| Backup dialog values             | Stored with the backup and       |
|                                  | replayed to its plans            |
+----------------------------------+----------------------------------+
| Restore dialog values            | Override matching stored custom  |
|                                  | values for that restore; leave   |
|                                  | the stored backup values         |
|                                  | unchanged                        |
+----------------------------------+----------------------------------+
| Invalid or repeated variable     | Confirmation is refused; no      |
|                                  | operation is started             |
+----------------------------------+----------------------------------+

**Delete several backups**

1. Open the Jet's **Backups** smart button, or **Cetmix Tower** →
   **Tools** → **Backups**.
2. Select the backups.
3. Click **Action** → **Delete** and confirm.
4. Wait for the Delete plans. Backups on the same Jet are processed one
   at a time; remaining requests are retained rather than skipped.
5. Inspect any **Deletion Failed** backup separately. Other selected
   backups continue; failed deletions require manual retry.

Queued backups cannot be restored. A queued backup's form shows that
deletion is pending. Daily cleanup retries requests deferred by
contention or dispatch errors.
