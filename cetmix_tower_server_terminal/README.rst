This module adds an interactive SSH terminal to `Cetmix
Tower <https://tower.cetmix.com>`__ servers. A manager opens a shell on
a server from its form view and works in it in the browser, with the SSH
credentials, host key and access rules Tower already stores for that
server. No SSH client, no credentials on the technician's machine.

The terminal runs on `xterm.js <https://xtermjs.org>`__, so colours,
cursor keys, window size and full screen programs such as ``top``,
``htop`` or ``vim`` behave as they do in a local terminal.

Please refer to the `official
documentation <https://tower.cetmix.com>`__ for detailed information.

Use Cases / Context
===================

Tower runs commands and flight plans that are written in advance, which
covers routine work but not troubleshooting: the moment something
unexpected happens, the technician leaves Tower, opens an SSH client and
works with credentials kept outside of it.

An interactive shell cannot be served the way a command is. It is a live
connection that has to stay in one process for its whole lifetime, while
Odoo serves each request from whichever worker is free. This module
keeps the shell in the process that serves the websocket of the browser,
and reaches it from the other workers through postgres notifications,
the same transport ``bus.bus`` uses.

Configuration
=============

To configure this module, you need to:

1. Go to "Cetmix Tower > Servers" and open the server you want to
   connect to.
2. Make sure its SSH settings work, using the "Test Connection" button.
   The terminal uses the same host, port, user, authentication mode and
   host key.
3. Give the "Cetmix Tower / Manager" group to the users who may open a
   terminal. The button is hidden for everyone else, and a user who is
   not a manager of the server does not see the server at all.

The following system parameter is optional:

- ``cetmix_tower_server_terminal.idle_timeout``: seconds a session may
  stay idle before it is closed, 1800 by default. Anything below 60 is
  raised to 60. A session reads it when it starts, so changing it leaves
  the terminals that are already open alone.

Odoo must be running its websocket worker, which is the case in any
standard deployment: terminal output travels through the Odoo bus. If
the bus does not reach the browser, the terminal reports the session as
unavailable instead of hanging.

Usage
=====

To use this module, you need to:

1. Go to "Cetmix Tower > Servers" and open a server.
2. Click the "Terminal" button in the header. A terminal opens,
   connected as the SSH user of the server.
3. Type as you would in any terminal. Window size, colours and control
   keys such as ``Ctrl+C`` are passed to the remote shell.
4. Click "Clear" to clear the screen, or "Disconnect" to close the
   session.
5. Click "Reconnect" to start a new session, for example after the shell
   exited or the session was lost.

While a session is open:

- the magnifier searches the output you have already received, and the
  arrows walk through what it finds;
- the expand button gives the terminal the whole window, which is what
  reading a long log asks for;
- scrolling up stops the terminal from following the output, so a page
  being read does not jump. A button appears when there is output you
  have not seen, and takes you back to it.

The terminal keeps a few shortcuts for itself; every other key goes to
the shell:

=========================== ======================================
shortcut                    what it does
=========================== ======================================
``Ctrl+Shift+F``            search the output
``Ctrl+Shift+C``            copy the selection
``Ctrl+Shift+V``            paste
``Enter`` / ``Shift+Enter`` next / previous match, while searching
``Esc``                     close the search
=========================== ======================================

Sessions do not outlive what they are attached to:

- closing the browser tab closes the session;
- a session nobody is connected to any more is closed after 30 seconds,
  so a network blink does not cost you your shell;
- an idle session is closed after 30 minutes;
- restarting Odoo closes every session. The terminal then reports the
  session as no longer available and offers to reconnect.

Each session is private to the user who opened it, and every session
opened is written to the Odoo log with the server and the user.
